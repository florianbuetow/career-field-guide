# Mock Interview Feedback Form

A fillable copy of the feedback form that mock interview partners complete for
each other after a session. Tick a box per question; the rubric tables below
each grid explain what each score stands for.

Giving and receiving feedback is a large part of getting better at coding
interviews. Spend a few minutes filling this out as honestly and specifically
as you can - your answers are meant to be shared with your partner.

## Interviewee Feedback

This section mirrors the structure of the feedback forms that interviewers at
large tech companies fill out for the candidates they interview.

### Performance

Score each dimension from 1 to 4.

#### Algorithms - [ ] 1  [ ] 2  [ ] 3  [ ] 4

| Score | What it means |
| :---: | ------------- |
| 1 | Could not arrive at a working algorithm, even with substantial guidance. Gaps in core data-structure and algorithm knowledge were clearly visible. |
| 2 | Reached an algorithm only after repeated hints. The approach was noticeably suboptimal and the complexity analysis was shaky or absent. |
| 3 | Reached a correct and reasonably efficient algorithm with little prompting, and analyzed its time and space complexity correctly. |
| 4 | Reached the optimal algorithm quickly and independently, and reasoned fluently about alternatives and their complexity trade-offs. |

#### Coding - [ ] 1  [ ] 2  [ ] 3  [ ] 4

| Score | What it means |
| :---: | ------------- |
| 1 | Struggled to turn the idea into code. The implementation stayed largely incomplete or never worked. |
| 2 | Produced working code only with help. It was disorganized or buggy, and the interviewer had to point out defects. |
| 3 | Wrote clean, mostly correct code at a steady pace and caught most of their own mistakes without help. |
| 4 | Wrote clean, correct, idiomatic code quickly, with sensible naming and edge cases handled before being asked. |

#### Communication - [ ] 1  [ ] 2  [ ] 3  [ ] 4

| Score | What it means |
| :---: | ------------- |
| 1 | Worked in silence, or explained their reasoning so unclearly that it was hard to follow what they were doing. |
| 2 | Explained some of their steps, but had to be asked repeatedly to think out loud or to clarify what they meant. |
| 3 | Narrated their thinking clearly, asked useful clarifying questions, and responded well to feedback during the session. |
| 4 | Communicated like a strong collaborator throughout: crisp explanations, well-chosen questions, and easy to follow at every step. |

#### Problem Solving - [ ] 1  [ ] 2  [ ] 3  [ ] 4

| Score | What it means |
| :---: | ------------- |
| 1 | Got stuck early and could not make meaningful progress, even after significant guidance. |
| 2 | Made progress mainly on the back of hints, and struggled to recover from wrong turns without help. |
| 3 | Broke the problem down methodically, tested ideas against examples, and recovered from dead ends with only light nudging. |
| 4 | Drove the problem from start to finish independently, spotted the key insight early, and validated it before writing any code. |

### Final Score

- [ ] Strong No Hire
- [ ] No Hire
- [ ] Leaning No Hire
- [ ] Leaning Hire
- [ ] Hire
- [ ] Strong Hire

| Rating | What it means |
| ------ | ------------- |
| Strong No Hire | Performance was clearly below the bar across the board. You would argue against hiring this candidate. |
| No Hire | Fell short of the bar on more than one dimension. You would not advance this candidate. |
| Leaning No Hire | Slightly below the bar. You have real reservations, but other rounds could change your mind. |
| Leaning Hire | Slightly above the bar. A few weak spots remain, but you would tentatively advance this candidate. |
| Hire | Met the bar comfortably on every dimension. You would advance this candidate without hesitation. |
| Strong Hire | Well above the bar. You would actively argue in favor of hiring this candidate. |

## Interviewer Feedback

For the "Hint Giving" field: if your partner gave you no hints because you never
needed one, give them the maximum score of 3.

**Did this person prepare the interview question ahead of time?**

- [ ] Yes
- [ ] No

### Performance

Score each dimension from 1 to 3.

#### Prompt Clarity - [ ] 1  [ ] 2  [ ] 3

| Score | What it means |
| :---: | ------------- |
| 1 | The question was explained confusingly or incompletely, and important requirements only surfaced much later. |
| 2 | The question was mostly clear, but some details had to be dragged out through follow-up questions. |
| 3 | The question was stated clearly and completely up front, with examples and constraints spelled out. |

#### Hint Giving - [ ] 1  [ ] 2  [ ] 3

| Score | What it means |
| :---: | ------------- |
| 1 | Hints were missing when they were badly needed, or so heavy-handed that they gave the solution away. |
| 2 | Hints were reasonable but mistimed - too early, too late, or bigger than the situation called for. |
| 3 | Hints were well-timed and minimal: enough to unblock without solving. Give a 3 if you never needed a hint. |

### Final Score

- [ ] Bad
- [ ] Mediocre
- [ ] Good
- [ ] Great

| Rating | What it means |
| ------ | ------------- |
| Bad | The session did not work as an interview simulation. You would not want to be matched with this partner again. |
| Mediocre | There was some value in the session, but it fell well short of a realistic interview experience. |
| Good | A solid, realistic interview simulation with feedback you can actually act on. |
| Great | An excellent interviewer: well prepared, realistic, and genuinely useful in their feedback. |

## About this form

The rubric descriptions in the tables above are original text written for this
guide. Adapt the wording, the dimensions, or the score ranges to match however
you run your mock interviews.

An interactive HTML version of the same form lives alongside this file at
`mock-interview-feedback-form.html`. There, each description appears when you
hover a score and stays put once you select one.
